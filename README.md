# Humanizer-zh · 小红书 AI 图文写作与润色

Humanizer-zh 小红书专用版（`humanizer-zh`）是一套开源图文写作与润色 Skill。可以从素材起稿，也可以改已有 AI 笔记的标题、正文、封面和逐页配图文案，并结合笔记反馈调整内容。改稿时保留事实、作者的判断和原有语气。

仅在用户或当前上下文已经明确小红书图文场景时使用。不用于抖音等短视频脚本、微信回复或通用文档润色；X、GitHub等可以是素材来源。调用名仍为 `humanizer-zh`，完整适用范围见 [SKILL.md](SKILL.md)。

这是一份由 Agent 读取执行的编辑指导，不是独立的检测程序。它不能证明文章由谁撰写，也不保证通过任何 AI 检测器。

> 小红书专用版 `2026-10-28-r4` 包含 31 项表达检查、AI 图文写作指导及按需反馈分析。[更新记录](CHANGELOG.md)

## 安装

克隆本仓库，或下载 ZIP 并解压，将得到的文件夹命名为 `humanizer-zh`。保留 `SKILL.md`、`references/` 和 `agents/` 的相对位置。

```bash
git clone https://github.com/wmc837911722-del/humanizer-zh.git
```

将整个 `humanizer-zh` 文件夹复制到对应位置。

| 助手 | 用户技能目录 |
| --- | --- |
| Codex | `~/.agents/skills/humanizer-zh/` |
| Claude Code | `~/.claude/skills/humanizer-zh/` |

Windows 上的 `~` 是用户目录 `%USERPROFILE%`。重新加载技能或开启新对话后，在 Codex 中使用 `$humanizer-zh`，在 Claude Code 中使用 `/humanizer-zh`。

## 使用

粘贴文本：

```text
请用 humanizer-zh 润色下面的小红书AI图文笔记，保留我的判断和事实：
[原文]
```

编辑文件：

```text
请用 humanizer-zh 润色小红书发布稿.md 中的正文。
```

只审阅时说明“给出建议，不修改文件”。有作者样本时可一并提供，Skill 会借鉴表达习惯，但不会把样本中的经历、数据或观点搬入原文。

## 改写示例

以下均为教学用输入，没有未展示的补充材料。

**产品介绍，缺少数据：**

> 原文：该方案稳定可靠、快速响应、易于维护。
>
> 改写：这套方案运行稳定、响应快，也方便维护。

没有补写上线时间、响应速度或维护成本。原文缺少证据，可以向作者索取，不能用润色补出数据。

**故障反馈，有不确定性：**

> 原文：该问题被社区多次报告，被认为可能与内存泄漏有关，但原因尚未确认。
>
> 改写：社区多次报告这个问题。它被认为可能与内存泄漏有关，但原因尚未确认。

保留“可能有关”和“尚未确认”，不把推测改成因果结论，也不把原因判断擅自归给社区。

**更新说明，有真实的三项功能：**

> 原文：这次更新彰显了团队对创新的追求。它新增导出、搜索和批量重命名。离线编辑计划在下一版推出，目前尚未完成测试。
>
> 改写：这次更新新增导出、搜索和批量重命名。离线编辑计划在下一版推出，目前尚未完成测试。

保留三个功能，不为避开三段式删项或凑项；计划和测试状态保持原意。

**已经清楚的文字：**

> 原文：先保存文件，再关闭窗口。未保存的修改会丢失。
>
> 改写：先保存文件，再关闭窗口。未保存的修改会丢失。

不要求每次调用都产生修改。

## 编辑原则

约束优先级是：保留信息和确定程度，遵守用户范围与文体，匹配作者声音，再处理具体表达问题。模式命中不能覆盖这些要求。

- 不编造功能、数据、来源、人物身份或第一人称经历。
- 保留否定、条件、归因、范围、时间和完成状态；“可能”不变成“确定”，“计划”不变成“已经”。
- 三项列表、四字格、被动句、破折号和连接词按作用判断，不机械删除。
- 观点笔记保留个性；引用学术、商务或技术材料时保留准确含义，不把所有笔记改成同一种口语。
- 文件编辑默认保留代码、命令、路径、链接目标、YAML、数据、标题和锚点。改标题或结构需要检查引用。
- 默认只交付最终稿，不要求展示中间草稿、命中清单或自评分。

## 模式目录

保留 31 个检查点，沿用 PR #39 的 A–F 分类，便于对照。这是编辑问题清单，不是作者身份检测标准。

| 分类 | 检查点 |
|---|---|
| A：铺垫代替陈述（1–5） | 假对比、戏剧性碎片、伪深度、起跑式铺垫、无对象的辩护 |
| B：公式化节奏（6–11） | 强凑三段式、重复开头、万能破折号、限定堆叠、生造复合词、被动与缺主语 |
| C：拔高与借权威（12–18） | 空泛高频词、意义拔高、模糊关联、句尾拔高、宣传语、权威背书、复杂系动词 |
| D：公式化排版（19–21） | 无效粗体、装饰性标题、引号和标点 |
| E：聊天与草稿残留（22–25） | 客服腔、重复免责与猜测填充、首句复读标题、编辑过程残留 |
| F：中文补充检查（26–31） | 长定语、“进行＋动词”、被字句堆叠、四字词排比、万能背景、套话收尾 |

每条包括修改条件、前后示例和保留边界，详见 [SKILL.md](SKILL.md)。

## 企业 AI 落地咨询与定制开发

面向正在评估、试点或上线 AI 应用的企业负责人、业务团队和技术团队。可以从一个具体流程开始，先看已有资料、系统接口和权限能否支撑，再决定做方案咨询、原型验证还是定制开发。

### 可以做哪些项目？

| 业务场景 | 服务内容 |
| --- | --- |
| **企业 AI 知识库与 RAG 问答** | 接入制度、产品手册和业务资料，设计文档更新、答案引用和访问权限。用真实业务问题和不同权限的测试账号，验收回答质量及可见范围。 |
| **AI 工作流与业务自动化** | 梳理文档信息提取、工单分流、报表整理等重复流程，明确 AI 处理、人工复核和异常处理分别在哪一步。 |
| **AI 定制开发与系统集成** | 根据现有 CRM、工单系统或协作平台的接口，评估模型和数据如何接入。按确认的范围开发业务工具、后端 API 或系统集成。 |

### 可以只做咨询吗？能交付什么？

可以。咨询可以交付场景优先级、技术选型建议、试点范围和验收标准。需要验证时，可以先做一个覆盖关键流程的原型。进入定制开发后，双方确认功能范围、交付物和验收方式，按约定交付源码、部署说明或使用文档。

### 怎么开始合作和报价？

扫上方微信二维码，说明一个想改善的流程、现有资料或系统，以及希望达到的结果。初次沟通提供需求概要和脱敏样例即可。报价按服务范围、数据与系统接入复杂度和交付内容评估。
